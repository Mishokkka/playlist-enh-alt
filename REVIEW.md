# Повторное ревью Playlist Enchantment

2 ноября 2026 года. Проверена локальная **1.3.9**, исправления установлены как **1.3.10**, целевой движок **Foundry 13.351**.

В 1.3.9 действительно были ошибки. Прежние 65 проверок были полезны для отдельных функций, но недостаточны для подтверждения совместимости воспроизведения: они преимущественно проверяли данные обновлений, а не весь путь через методы документов, внутренние операции Sound и события аудио.

Для повторной проверки написан отдельный набор регрессий. Он запущен против сохранённой копии 1.3.9: **12 сценариев из 12 падают**. На исправленной версии все 12 проходят. Это повторная проверка по отдельным критериям и воспроизводимым сценариям; внешняя сторонняя сертификация не проводилась.

## Подтверждённые проблемы 1.3.9

| Приоритет | Ошибка и её причина | Исправление |
| --- | --- | --- |
| P1 | Crossfade напрямую вызывал `playlist.update()` и обходил `playAll()`, `playSound()`, `stopAll()` | Возвращены публичные методы. В установленном The Sound of Silence на них завязаны очистка таймеров, внутренние циклы, паузы и репликация |
| P1 | Старый плейлист останавливался параллельно с запуском нового. Ошибка метода запуска оставляла мир без прежней музыки | Остановка других плейлистов начинается после успешного завершения публичного метода запуска; отменённый/пустой запуск сохраняет старое воспроизведение |
| P2 | Разовый macro fade записывался в постоянное поле `Playlist.fade` | Длительность передаётся в параметрах операции, принимается клиентским жизненным циклом и очищается после применения |
| P1 | Возобновление части одновременного плейлиста обходило `playSound()` и его обёртки | Полный одновременный набор возобновляется одним `playAll()`, частичный — через `playSound()` |
| P2 | Проверка повторных загрузок игнорировала регистр имени файла | Сохраняется регистр: `battle.ogg` и `BATTLE.ogg` не считаются одним файлом |
| P2 | Имя из browse декодировалось повторно при построении ключа. `song%20one.ogg` могло спутаться с `song one.ogg` | Browse-имя декодируется один раз и сравнивается с буквальным `File.name` |
| P2 | Параллельные изменения настроек клонировали один старый объект и теряли первое изменение | Запись сериализована; каждый следующий запрос читает последнее подтверждённое значение |
| P2 | Повторный `popup.close()` завершался раньше настоящего закрытия, а глобальная ссылка очищалась до teardown | Возвращается общий Promise закрытия; новый popup ждёт освобождения прежнего экземпляра |
| P2 | Поздний stop старого Sound мог отменить таймер уже нового Sound того же документа | Таймер привязан к конкретному источнику и его событиям, обработчики удаляются при отмене |
| P2 | Оптимизированный таймер не участвовал в публичном `Sound.unscheduleAll()` | Отмена теперь охватывает и новый таймер; сохраняется исходный метод Sound. Raw pause/stop/end также снимают таймер |
| P2 | Проверка чужого планировщика сравнивала два метода одного изменяемого прототипа и могла не заметить установленную обёртку | Исходные методы фиксируются при загрузке модуля; установка выполняется в setup после конфигурации init |
| P2 | Строка удалённого звука могла оставаться в popup до обновления, а действия обращались к отсутствующему документу | Перед воспроизведением и изменением громкости проверяется живой документ |

Регрессии находятся в `tests/review-regressions.test.mjs`. Сохранённый вывод падающего прогона: `playlist-enchantment-audit/review/regressions-against-1.3.9.txt` рядом с резервными копиями.

## Исправление жизненного цикла

В `modules/playback-lifecycle.js` введено сопровождение переходов через штатную операцию Foundry. Оно добавляет временные параметры в `options`, а не в сохраняемые данные документа. Возможность переноса options проверена по установленному `client/data/client-backend.mjs`: параметры, изменённые pre-update hooks, переносятся в операцию и передаются клиентским `_onUpdate()`.

Документные подклассы вызывают унаследованные методы и сохраняют их обёртки. Временная длительность доступна при запуске/остановке; планировщик fade в конце песни получает исходное сохранённое значение. Для каждого плейлиста действует отдельная очередь, чтобы одновременные команды не подменяли контекст друг друга. После успеха и после ошибки временные параметры удаляются.

Проверка на полном клиентском коде обнаружила два дополнительных случая, которые прежние тесты отдельных методов пропускали:

- Старый файл мог закончить загрузку после смены источника. Его play/end события теперь проверяют принадлежность текущему Sound. Устаревший источник останавливается после завершения синхронной фазы `Sound.play`, чтобы не попасть в гонку с присваиванием его внутреннего Promise операции.
- Асинхронная обёртка `_onStart()` могла получить исходный fade, если временный контекст удалялся сразу после вызова. Очистка теперь ожидает завершения унаследованного обработчика.

При возобновлении во время затухания используется уже существующее поведение v13: `Sound.playing` исключает состояние STOPPING, а `Sound.load()` ожидает текущую операцию остановки. Дополнительное ожидание или опрос состояния для этого не вводится.

Явный macro crossfade задаёт разовую длительность перехода. Обычный fade в конце дорожки и сохранённые `Playlist.fade` / `PlaylistSound.fade` остаются самостоятельными значениями. Включённый пользователем глобальный параметр always-Fade по-прежнему намеренно обновляет настройку плейлиста, как в прежней версии модуля.

## Производительность и совместимость

Оптимизация длинного буфера таймера сохранена. Расчёт около 55 МиБ на пять минут при 48 кГц подтверждается кодом установленного `AudioTimeout`. Это расчёт запрашиваемого буфера, а не измерение расхода RAM или доказательство причины всех статтеров.

Кеш строк, отсутствие синтетических событий громкости и лишних рендеров, делегированные обработчики и пропуск скрытых поверхностей сохранены. Тест 1000 строк × 30 неизменившихся тиков продолжает давать ноль запросов селекторов и ноль перезаписей текста после создания кеша.

Быстрый пакетный путь используется, когда его выражает публичный API: например, возобновление всех 100 одновременных дорожек одним `playAll()`. Для частичного выбора или остановки отдельных каналов используются методы дорожек; там запросов может быть больше, чем у прямого обновления 1.3.9. Это позволяет исполнить очистку и обработчики активных модулей.

Исходники установленного The Sound of Silence просмотрены в части `playAll`, `playSound`, `stopAll`, `stopSound`, `sync` и отмены fade. Сохранение вызовов обёрток проверено, но полное исполнение всех функций этого аддона в работающем мире не выполнялось. Если сторонний модуль полностью переопределяет операцию и собственную репликацию с `noHook`, его правила fade имеют приоритет.

## Что проверено

Всего **92 проверки**:

- 31 — интерфейс, управление, громкость, шаблоны и загрузки;
- 16 — аудиопланировщик и его отмена/восстановление;
- 18 — расположения файлов;
- 12 — воспроизводимые регрессии 1.3.9;
- 15 — полный клиентский жизненный цикл воспроизведения.

Последний набор использует тела настоящих классов `Sound`, `PlaylistSound`, `Playlist`, `AudioTimeout` и `EventEmitterMixin` из установленного Foundry, включая приватные поля и очереди операций. Аудиоустройство, базовая модель данных, хранение и транспорт заменены управляемыми тестовыми границами. Проверены запуск с задержкой, остановка и возобновление того же Sound, передача сериализованной операции второй модели клиента, одновременные дорожки с нулевой громкостью, устаревшие источники и асинхронные обработчики.

Тесты проверяют ожидаемое поведение, а не только сходство результата с написанной реализацией. Часть прежних проверок изменена, поскольку она закрепляла ошибочную запись fade или обходила настоящий жизненный цикл звука.

## Пределы проверки и применение

**FPS живого мира, реальное Web Audio устройство, сетевой обмен между подключёнными игроками и весь набор активных аддонов не проверены вживую.** Доступ к окну Foundry и изолированному браузерному прогону ранее был отклонён инструментами. Результаты тестов не заменяют этот прогон и не дают основания гарантировать устранение всех статтеров.

Успешный ответ метода запуска подтверждает операцию документа. Он не гарантирует, что асинхронно загружаемый файл затем декодируется и будет слышен; остановка прежнего плейлиста не ожидает физического вывода звука.

Код установлен в вашей папке. Для применения 1.3.10 перезапустите Foundry и перезагрузите клиентов игроков. Клиентский переключатель Optimize fade timers позволяет отдельно сравнить оптимизацию таймеров после перезагрузки.

Копия 1.3.9 сохранена в `playlist-enchantment-audit/review/backup-1.3.9`; исходная пользовательская 1.3.8 также сохранена. Значения fade, которые 1.3.9 могла уже записать в мир, не содержатся в резервной копии файлов модуля. Их прежние значения можно достоверно восстановить по резервной копии самого мира; автоматически угадывать их этот патч не пытается.
